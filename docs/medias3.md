# Media System Architecture - S3 & Cloudflare R2 Integration

> Complete documentation for KAWAI's unified media optimization system

## Overview

The KAWAI media system provides a sophisticated, production-ready pipeline that transforms simple uploads into optimized, responsive media delivery through Cloudflare R2 storage and on-the-fly image processing.

### Architecture Flow
```
📷 Upload → 🗄️ Payload CMS → ☁️ Cloudflare R2 → 🔍 URL Transform → 🚀 Optimized Frontend
```

**Core Principle**: Single pipeline handles both Payload Media objects and string URLs uniformly.

## S3 Adapter Configuration

### Payload Configuration (`src/payload.config.ts`)
```typescript
import { s3Storage } from '@payloadcms/storage-s3'

export default buildConfig({
  // ... other config
  plugins: [
    s3Storage({
      collections: {
        'media': {
          prefix: 'media',
          disablePayloadAccessControl: true, // Enable direct R2 URLs
          generateFileURL: ({ filename, prefix }) => {
            const publicUrl = process.env.NEXT_PUBLIC_S3_PUBLIC_URL
            const cleanPublicUrl = publicUrl.replace(/\/$/, '')
            const path = prefix ? `${prefix}/${filename}` : filename
            return `${cleanPublicUrl}/${path}`
          },
        },
      },
      bucket: process.env.S3_BUCKET,
      config: {
        endpoint: process.env.S3_ENDPOINT,
        region: process.env.S3_REGION || 'auto',
        credentials: {
          accessKeyId: process.env.S3_ACCESS_KEY_ID,
          secretAccessKey: process.env.S3_SECRET_ACCESS_KEY,
        },
        forcePathStyle: true, // Required for Cloudflare R2
      },
    }),
  ],
})
```

## Troubleshooting Guide

### Common Issues & Solutions

#### 1. Images Not Loading
**Symptoms**: Images show as broken or don't load
**Check**:
- `NEXT_PUBLIC_S3_PUBLIC_URL` environment variable
- R2 bucket public access settings
- Network tab for 404/403 errors

**Solutions**:
```bash
# Verify environment variable
echo $NEXT_PUBLIC_S3_PUBLIC_URL

# Test direct R2 access
curl -I "https://pub-subdomain.r2.dev/media/test-image.jpg"
```

#### 2. Images Not Optimized
**Symptoms**: Large file sizes, no WebP format, single resolution
**Check**:
- Component usage (`MediaRenderer` vs raw `img`)
- Preset configuration
- Browser network tab for transformation parameters

**Debug**:
```typescript
// Enable debug logging
const imageProps = getOptimizedImageProps(media, 'hero')
console.log('Generated image props:', imageProps)
```

#### 3. Poor Performance
**Symptoms**: Slow loading, large LCP, no progressive loading
**Check**:
- Priority setting for above-fold images
- LQIP generation
- Lazy loading configuration

**Solutions**:
```tsx
// Ensure hero images have priority
<MediaRenderer media={heroImage} preset="hero" priority={true} />

// Check LQIP generation
const lqip = generateLQIP(filename)
console.log('LQIP URL:', lqip)
```

#### 4. TypeScript Errors
**Symptoms**: Type errors with Media objects
**Check**:
- Generated Payload types
- Import statements
- Media object structure

**Solutions**:
```bash
# Regenerate Payload types
bun run build

# Check type imports
import type { Media } from '@/payload-types'
```

## Best Practices

### 1. Always Use the Unified Pipeline
```tsx
// ✅ Correct - uses optimization pipeline
const imageProps = getOptimizedImageProps(media, 'gallery')

// ❌ Avoid - bypasses optimization
<img src={media.url} alt={media.alt} />
```

### 2. Choose Appropriate Presets
```tsx
// ✅ Correct preset usage
'hero'      // Large hero images, landing pages
'gallery'   // Product showcases, category images  
'thumbnail' // Small previews, navigation
'card'      // Product cards, listings

// ❌ Avoid - wrong preset for use case
<MediaRenderer media={thumbnailImage} preset="hero" /> // Oversized
```

### 3. Handle Both Media Types
```tsx
// ✅ Flexible function signature
function renderImage(media: Media | string) {
  if (typeof media === 'object') {
    // Media object with .url, .alt, .width, .height
    return <MediaRenderer media={media} preset="gallery" />
  } else {
    // String URL - still optimized through same pipeline
    return <MediaRenderer media={media} preset="gallery" />
  }
}
```

### 4. Implement Proper Error Handling
```tsx
// ✅ Comprehensive error handling
<ResponsiveImage
  media={pianoImage}
  preset="hero"
  fallback="/images/piano-placeholder.jpg"
  onError={(error) => {
    // Log to monitoring service
    console.error('Image load failed:', error)
  }}
/>
```

### 5. Optimize for Performance
```tsx
// ✅ Performance-first approach
{images.map((image, index) => (
  <MediaRenderer
    key={image.id}
    media={image}
    preset="gallery"
    priority={index < 3}        // Above-fold priority
    placeholder={index >= 3}    // LQIP for below-fold
  />
))}
```
