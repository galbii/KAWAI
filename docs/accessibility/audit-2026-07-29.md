## Confirmed violations (prioritized)

### P1 — Systemic contrast: opacity-modified text tokens (1.4.3)
The dominant failure across all three sub-100 pages. `text-kawai-charcoal/{25–60}`, `text-kawai-black/{20–55}`, `text-white/{20–55}` all fail 4.5:1 (charcoal/50 on white ≈ 2.8:1; /60 ≈ 3.9:1).

Usage counts (src/): charcoal/40 ×167, charcoal/50 ×162, charcoal/60 ×94, charcoal/35 ×51, black/40 ×35, white/50 ×73, white/40 ×36, white/35 ×33 … **183 files affected** in the ≤/60 charcoal+black range alone.

Fix: replace sub-`/60` dark-on-light text with `text-kawai-muted` (#595959, 7:1 — token already exists) and sub-`/70` white-on-dark with `/70`+ or solid tones. Hotspots seen live: `PianosBrowser.tsx` (filter labels, breadcrumb), `accessories-page-content.tsx`, store newsletter modal (floating labels `black/45`, fine print `/40`), blog sidebar. Note text at /70+ generally passes — only sub-/60-ish values need touching. Opacity on *decorative/disabled* elements is fine.

Additional specific contrast bugs:
- `blocks/ProductHeroBlock.tsx:1012` — both ternary branches emit `text-kawai-red` (should be `kawai-red-400` on black bg)
- `blocks/VideoBackgroundBlock.tsx:168` — `text-kawai-red/95` over dark video
- `blocks/CollectionShowcaseBlock.tsx:136` — inactive tab `text-white/40` (~2.7:1)
- `assessment/AssessmentProgress.tsx:153` — `text-gray-400` on `bg-gray-100`

### P2 — Forms: labels not programmatically associated (1.3.1 / 4.1.2)
Visible `<label>` with no `htmlFor`, inputs with no `id` — screen readers announce nothing. Confirmed across user-facing lead forms:
`contact/LocationContactForm.tsx` (233–399), `homepage/contact-form.tsx` (419–450), `trade-in/AppraisalForm.tsx`, `trade-in/BookingModal.tsx`, `pages/signature/DualConversion.tsx`, `grand-spring-sale/SaleLeadForm.tsx`, `store/[storeslug]/the-gift-of-music/page.tsx` (10 inputs), `forms/ConstantContactForm.tsx:316`. (Admin-tool forms share the pattern; lower priority.)

Placeholder-only search inputs (no aria-label): `piano/search-filter.tsx:276`, `piano/product-browser.tsx:120`, `piano/enhanced-series-browser.tsx:312`, `storefronts/StorefrontsGrid.tsx:111`.

### P3 — Icon-only controls with no accessible name (4.1.2)

### P4 — Hand-rolled modals without dialog semantics (2.1.2 / 4.1.2)
`useModal` hook provides scroll-lock only — no focus trap/Escape/restore. Affected: `ui/EmailCapturePopup.tsx`, `ui/showroom-cta.tsx` (modal variant), `piano/comparison.tsx`, `pages/signature/{ExitIntentModal,QuickContactModal,ConsultationBookingModal}.tsx`; `MediaLightbox.tsx` + `image-gallery-lightbox.tsx` have Escape but no role/trap/restore. Fix: migrate to `ui/modal.tsx` (Radix — already compliant).

### P5 — Motion: auto-advance with no pause + no reduced-motion (2.2.2)

### P8 — Alt-text plumbing (1.1.1, systemic risk)
`lib/media/r2-utils.ts:464` `getImagePropsWithFallback()` always returns `alt: ''` and never reads CMS `Media.alt` — every consumer must manually re-supply alt or ships empty. Recommend the helper propagate `cmsImage.alt`. Also `blocks/ImageBlock.tsx:48` falls back to `alt=""` for meaningful images.
