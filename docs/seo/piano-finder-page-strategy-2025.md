## 4. Page Architecture Recommendation

### RECOMMENDED: Single Comprehensive Pillar Page

**Why NOT Multiple Separate Pages:**
- Creating `/find-my-piano/by-sound`, `/by-budget`, `/by-use-case` would compete for the SAME primary keyword: "piano finder"
- Intent cannibalization - these would all serve the same core intent: "help me choose a piano"
- Research shows: "Intent cannibalization" is the hidden problem in fragmented page strategies

**Why ONE Comprehensive Page Works Better:**
- Single URL consolidates all ranking signals (backlinks, engagement, authority)
- Serves multiple intents through structured sections
- No navigation friction - everything in one place
- Easier to rank one strong page than multiple weak ones

## 5. Technical SEO Implementation

### Server-Side Rendering Strategy

```typescript
// app/find-my-piano/page.tsx
export const revalidate = 300 // ISR: 5-minute cache

export const metadata = {
  title: 'Piano Finder - Find Your Perfect Kawai Piano | Interactive Tool',
  description: 'Use our expert piano finder to discover the perfect Kawai piano for your needs, budget, and goals. Get personalized recommendations in 7 questions.',
  keywords: 'piano finder, find the right piano, piano selection tool, which piano should I buy'
}

export default async function PianoFinderPage() {
  // Server-side data fetching
  const pianos = await getAllPianos()
  const faqs = await getFAQs('piano-finder')

  return (
    <div>
      {/* Static, crawlable intro content */}
      <IntroSection /> {/* Server Component */}

      {/* Quiz schema */}
      <script type="application/ld+json">
        {JSON.stringify(quizSchema)}
      </script>

      {/* Interactive tool */}
      <Suspense fallback={<QuizSkeleton />}>
        <PianoFinderQuiz initialData={pianos} /> {/* Client Component */}
      </Suspense>

      {/* Supporting content - Server Components */}
      <GuideContent />
      <ComparisonSection />
      <FAQSection faqs={faqs} />

      {/* FAQ schema */}
      <script type="application/ld+json">
        {JSON.stringify(faqSchema)}
      </script>
    </div>
  )
}
```

### Schema Markup Strategy

**Implement 4 Schema Types:**

1. **Quiz Schema** (Primary)
   - Makes page eligible for Q&A carousel in Google Search
   - Include all 7 questions with answer options

2. **FAQPage Schema**
   - 8-12 common piano selection questions
   - Targets featured snippets

3. **HowTo Schema**
   - "How to Choose a Piano" guide section
   - Step-by-step decision framework

4. **Product Schema**
   - For each recommended piano in quiz results
   - Include ratings, pricing, availability

### Core Web Vitals Targets (2025 Standards)

| Metric | Target | Why It Matters |
|--------|--------|----------------|
| **LCP** | <2.0s | First question/content visible quickly |
| **INP** | <150ms | Smooth quiz interactions (new in 2025) |
| **CLS** | <0.05 | Stable layout during quiz |
| **FCP** | <1.5s | Initial paint speed |

**CRITICAL:** INP (Interaction to Next Paint) replaced FID in 2025 - measures responsiveness across ALL interactions, not just first click.

### Mobile Optimization

**Mobile-First Considerations:**
- 60%+ of traffic will be mobile
- Quiz should be full-screen modal on mobile
- Swipe gestures for next/previous
- Larger tap targets (48px minimum)
- Results as vertical cards, not table

**Progressive Enhancement:**
```tsx
// Quiz works as HTML form without JavaScript
<form action="/api/piano-finder/submit" method="POST">
  {/* Accessible HTML question structure */}
  <QuestionStep />

  {/* Fallback submit button */}
  <noscript>
    <button type="submit">Get Recommendations</button>
  </noscript>

  {/* Enhanced navigation (requires JS) */}
  <NavigationButtons />
</form>
```
